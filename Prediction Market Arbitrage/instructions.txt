STEP 8 - Understand the real paper-trading mode

The real development mode should use live market data.

The live-data paper mode:

- connect to Kalshi and Polymarket normally
- listen to live order books and WebSockets
- find real market pairs
- calculate real entry prices from the order books
- record the market pair, entry prices, size, expected profit, and timestamp
- not send an order to either exchange
- keep each paper position open until the markets resolve
- generate a report after resolution showing what would have happened

Because this arbitrage strategy does not use take-profit or stop-loss exits, the
bot usually cannot know the final result immediately. It needs settlement data.
Short-duration crypto markets are useful for testing because they resolve often.

To discover real Bitcoin markets and auto-pairs without entering paper
positions, copy and paste:

PYTHONPATH=src python -m arb_bot.cli discover --config configs/config.example.toml --db data/discovery_bitcoin.sqlite3 --query bitcoin --limit 25 --fresh-db

To run the live-data paper bot for 10 minutes, copy and paste:

PYTHONPATH=src python -m arb_bot.cli paper --config configs/config.example.toml --db "data/session_$(date +%Y%m%d_%H%M%S).sqlite3" --query bitcoin --max-seconds 600 --fresh-db

To run a short 60-second test instead:

PYTHONPATH=src python -m arb_bot.cli paper --config configs/config.example.toml --db "data/session_$(date +%Y%m%d_%H%M%S).sqlite3" --query bitcoin --max-seconds 60 --fresh-db

If there are no equivalent Polymarket/Kalshi pairs, the bot will still record
markets discovered and WebSocket health, but it will not open paper positions.

STEP 10 - API validation before live-data paper trading and live trading

Before the bot can safely run against real live markets, both APIs need to be
validated. This does not mean live trading. It means checking that the bot can
read real market data correctly before it ever sends orders.

Read this file:

docs/api_verification.md

For Kalshi, validate:

- the key.txt file can authenticate successfully
- market lookup works
- BTC and other short-duration crypto markets can be discovered, if available
- order book depth can be fetched
- WebSocket updates work
- timestamps are precise enough
- settlement/resolution status can be checked later for reports
- fees are understood
- order types are known
- partial fills are reported clearly
- cancel behavior is understood
- rate limits are known

For Polymarket, validate:

- the polykey.txt file can authenticate successfully, if private endpoints are needed
- market lookup works
- BTC and other short-duration crypto markets can be discovered, if available
- order book depth can be fetched
- WebSocket updates work
- timestamps are precise enough
- settlement/resolution status can be checked later for reports
- fees are understood
- order types are known
- partial fills are reported clearly
- cancel behavior is understood
- rate limits are known

Do not enable live market paper mode until market data validation passes. Do not
enable live trading until both market data and order execution validation pass.
