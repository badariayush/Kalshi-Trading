Kalshi Crypto Live-Data Run Instructions
========================================

Safety boundary
---------------
- Only live WebSocket data runs are operator-supported.
- Real account order submission is disabled: order_api.allow_order_submission = false.
- Do not put API keys, private keys, or secrets in this repo.
- Stop immediately if any command prints order_submission=enabled.

Current live-only boundary
--------------------------
- The CLI exposes live-data capture/reporting only.
- The report command only accepts audit databases produced by live-data.
- The live-data command requires an actual Kalshi market ticker and Kalshi
  WebSocket auth environment variables.
- The program does not submit real orders and does not print simulated fills,
  sells, or profit. The only simulated action is a terminal/audit line for a
  would-place order, and only after live Kalshi and live Coinbase data are seen.

From the project root
---------------------
cd "/Users/ayushbadari/Documents/GitHub/Kalshi Trading/Kalshi-Crypto"

1. Run automated checks
-----------------------
PYTHONPATH=src python3 -m unittest discover -s tests

Stop if this fails.

2. Export Kalshi WebSocket credentials
--------------------------------------
Export these in your shell. Do not save them in any project file.

export KALSHI_KEY_ID="your_key_id"
export KALSHI_PRIVATE_KEY_PEM='-----BEGIN PRIVATE KEY-----
...
-----END PRIVATE KEY-----'

3. Confirm live-readiness state
-------------------------------
PYTHONPATH=src python3 -m kalshi_crypto.cli doctor-live-data --config configs/live.example.toml

Expected lines:
live_network=enabled
order_api=enabled
order_submission=disabled
kalshi_ws_url=wss://external-api-ws.kalshi.com/trade-api/ws/v2
coinbase_ws_url=wss://advanced-trade-ws.coinbase.com

4. Run the live-data program for BTC 15m and ETH 15m
----------------------------------------------------
The exact Kalshi market tickers change every 15 minutes. Before running, set
these two variables to the currently open Kalshi BTC 15m and ETH 15m market
tickers from Kalshi:

export BTC_15M_KALSHI_TICKER="replace_with_current_btc_15m_kalshi_market_ticker"
export ETH_15M_KALSHI_TICKER="replace_with_current_eth_15m_kalshi_market_ticker"

Run BTC 15m only:

PYTHONPATH=src python3 -m kalshi_crypto.cli live-data --config configs/live.example.toml --kalshi-market-ticker "$BTC_15M_KALSHI_TICKER" --output-file /private/tmp/kalshi-btc-15m-live-capture.jsonl --audit-db /private/tmp/kalshi-btc-15m-live.sqlite3 --max-seconds 600

Run ETH 15m only:

PYTHONPATH=src python3 -m kalshi_crypto.cli live-data --config configs/live.example.toml --kalshi-market-ticker "$ETH_15M_KALSHI_TICKER" --output-file /private/tmp/kalshi-eth-15m-live-capture.jsonl --audit-db /private/tmp/kalshi-eth-15m-live.sqlite3 --max-seconds 600

Run BTC 15m and ETH 15m together:

PYTHONPATH=src python3 -m kalshi_crypto.cli live-data --config configs/live.example.toml --kalshi-market-ticker "$BTC_15M_KALSHI_TICKER" --kalshi-market-ticker "$ETH_15M_KALSHI_TICKER" --output-file /private/tmp/kalshi-btc-eth-15m-live-capture.jsonl --audit-db /private/tmp/kalshi-btc-eth-15m-live.sqlite3 --max-seconds 600

Expected lines:
network=attempted
execution=not_attempted
order_submission=disabled
kalshi_messages greater than 0
coinbase_messages greater than 0
feed_unhealthy_events=0
simulated_orders=1 when a live Kalshi ask and live Coinbase price were both observed

Stop if:
- the command errors
- order_submission is enabled
- kalshi_messages is 0
- coinbase_messages is 0
- feed_unhealthy_events is greater than 0

If a simulated order can be formed from the live feeds, the terminal prints one
line like:

simulated_order_placed=market_ticker=<KALSHI_MARKET_TICKER> side=yes price=<LIVE_KALSHI_PRICE> quantity=1 coinbase_product_id=<BTC-USD_OR_ETH-USD> coinbase_price=<LIVE_COINBASE_PRICE> source=live_feeds execution=simulated_print_only order_submission=disabled

That line is not a real order, not a fill, and not a profit/loss result.

5. Run the live-data report
---------------------------
BTC 15m report:

PYTHONPATH=src python3 -m kalshi_crypto.cli report --audit-db /private/tmp/kalshi-btc-15m-live.sqlite3

ETH 15m report:

PYTHONPATH=src python3 -m kalshi_crypto.cli report --audit-db /private/tmp/kalshi-eth-15m-live.sqlite3

BTC 15m and ETH 15m combined report:

PYTHONPATH=src python3 -m kalshi_crypto.cli report --audit-db /private/tmp/kalshi-btc-eth-15m-live.sqlite3

Expected live-data report lines:
status=no_trades
feed_unhealthy_events=0
execution_failures=0
simulated_orders matches the number of printed simulated_order_placed lines

The report is expected to show no_trades because this product currently captures
and audits live market data only. Real account execution, simulated fills, and
simulated profit/loss are not part of the live-only run surface.
